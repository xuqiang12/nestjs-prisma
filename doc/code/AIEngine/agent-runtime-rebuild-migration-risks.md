# AI Agent 运行时重构迁移风险记录

## 敏感词配置管理迁移

本次迁移将敏感词配置管理从 `/ai-platform/sensitive-word` 切换到 `/ai-config/sensitive-word`，旧接口不再保留。

本次迁移已删除旧配置管理代码。测试完成后，需要继续检查并删除旧引用和旧测试期说明，避免后续误以为 `/ai-platform/sensitive-word` 仍然可用。

## 后续可优化问题

1. 流式输出敏感词检查风险

当前流式输出会先 `yield event` 给前端，最后才做输出敏感词检查。如果模型流式吐出了敏感内容，最终检查只能保护落库内容，不能保护已经发给前端的内容。

这个问题不建议混在配置管理迁移里顺手修，因为它会改变流式输出策略。后续应单独设计安全流式输出方案，例如在输出给前端前做分段缓冲和敏感词处理。

2. `record` 处理方式没有审计落库

当前 `record` 只会作为命中结果返回，不会写入审计表或运行日志。如果后续需要追踪敏感词命中记录，需要单独设计记录位置和保留策略。

3. 简单字符串匹配能力有限

当前敏感词匹配依赖字符串包含判断，未处理大小写归一、分词、重叠词和变体绕过。是否增强匹配能力应结合真实安全等级和误伤成本单独评估。
